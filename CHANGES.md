# Что изменилось

## Как это выкатить (порядок важен)

1. Бэкап: Supabase → Database → Backups (или экспорт таблицы `users`).
2. Supabase → SQL Editor: выполни **`sql/01_setup.sql`**. Он только добавляет; если на этом шаге появится ошибка про view,
   зависящее от `users.password`, — пересоздай это view без колонки и запусти скрипт снова (ничего не потеряется).
3. Запусти **`sql/99_verify.sql`** — должно быть «ВСЕ ПРОВЕРКИ ПРОШЛИ». Если нет — не выкатывай дальше и пришли мне текст ошибки.
4. Замени файлы репозитория файлами из архива и **удали** файлы из списка ниже. Запушь в `main`.
   (Сайт соберётся только если проходят проверка типов и тесты.)
5. Когда новая версия сайта открылась и вход работает: выполни **`sql/02_lockdown.sql`**, затем **`sql/03_storage.sql`**.
   До шага 5 прямой доступ к таблицам ещё открыт; после — закрыт.

> **Важно:** в SQL Editor запускай ТОЛЬКО файлы `01_setup.sql`, `02_lockdown.sql`, `03_storage.sql`, `99_verify.sql`.
> Старые `passwords.sql`, `security.sql`, `migrate-users-to-auth.sql`, `block_reactions.sql` не запускать — они от прежних
> схем и конфликтуют с новой (дают ошибки вроде «cannot change return type» и «column password does not exist»).

### Удалить из репозитория
`vite.config.js`, `vite.config.d.ts`, `tsconfig.tsbuildinfo`, `tsconfig.node.tsbuildinfo`,
`sql/passwords.sql` (если есть), `sql/security.sql`, `sql/migrate-users-to-auth.sql`, `sql/block_reactions.sql`, `scripts/migrate-users-to-auth.mjs`.

## Что заметят пользователи

- **Все один раз выйдут из аккаунта** (сессия теперь — токен, а не имя) и войдут заново.
- Пароль при регистрации и смене — **от 6 символов** (старые короткие пароли продолжают работать для входа).
- Писать в личку можно только при **взаимной** дружбе; в «Друзьях» появился блок «Добавили тебя» с кнопкой «В ответ».
- Предупреждения администрации показываются окном, пока не нажмёшь «Понятно», и сохраняются в Настройках.
- Удаление аккаунта требует пароль; аккаунт админа удалить нельзя.
- Текстовые блоки получили панель оформления (размер, шрифт, курсив, цвет) — раньше поля были, а интерфейса не было.
- Стена прокручивается, если блоки выходят за экран; блоки нельзя утащить в минус.
- Вместо молчаливой очистки «неправильного» логина (кириллица → пустая строка) показывается понятная ошибка.

## Исправленные недочёты (по номерам из отчёта)

**Потеря данных:** 1 разлогин при сбое сети — сессия больше не сбрасывается, показывается «Повторить»; 2 сбой чтения
стены больше не превращается в «пустую» стену и блокирует сохранение; 3 лимит 1000 строк — постраничная загрузка,
чат показывает последние 300 + «Показать более ранние»; 4 перезапись чужих правок — версия стены, при конфликте выбор
«перезаписать / загрузить актуальную»; 5 выход из режима правки без сохранения теперь спрашивает; 6 имя админа
зарезервировано в SQL, аккаунт админа не удаляется; 7–8 файлы чистит `npm run purge-media`, схема БД в `sql/01_setup.sql`.

**Безопасность:** 9 личные сообщения — только через функции с проверкой токена, Realtime убран; 10 бан, предупреждения,
смена пароля, удаление, журнал — только админу и проверяются на сервере; 11 сессия — серверный токен; 12 защита от
перебора, пароль от 6; 13 тип/размер файлов проверяются и в клиенте, и в бакете; 14 лимит для картинок в чате;
15 строка-фильтр `.or(...)` убрана; 16 базу можно подменить через `.env`.

**Интерфейс:** 17 ресайз не «уезжает» и учитывает поворот (+ `pointercancel`); 18 прокрутка полотна; 19 музыка —
реальный прогресс, перемотка, обработка ошибок, `preload=none`; 20 гонка в выборе файла; 21 откат реакций при ошибке,
чистка реакций удалённых блоков; 22 гонка загрузки стены, обновление только друзей, `beforeunload` только при
несохранённом; 23 входящие заявки, обновление списков раз в 15 с; 24 «прочитано» только когда чат виден, IME,
защита от устаревших ответов; 25 эмодзи в аватаре, неправдивая «зелёная точка» убрана; 26 предупреждения; 27 точечное
обновление профиля вместо перезаписи целиком; 28 админка одним запросом; 29 мёртвый код, `flushSync` в переходах,
«На сайте с …»; 30 `ErrorBoundary`, запасное меню без popover; 31 подписи полей, клавиатура, aria-label, `role=alert`.

**Сборка и тесты:** 32 `tsc -b` больше не плодит `vite.config.js`; 33 иконки и манифест вынесены в `public/`
(`index.html` 273 КБ → 2 КБ); 34 e2e не привязан к Windows и удаляет за собой тестового пользователя; 35 тестов 37 → 56
(сбои сети, конфликт версий, взаимная дружба, пароль при удалении, предупреждения, ресайз, типы файлов);

## Что НЕ сделано (честно)

- **Тесты и SQL я не запускал на настоящих vitest/Postgres** — в моей среде нет сети. Тесты прогнаны самодельным
  раннером (esbuild + jsdom): 56/56. SQL проверен чтением; поэтому есть `sql/99_verify.sql`.
- Загрузка в Storage по публичному ключу остаётся открытой (иначе без Supabase Auth её не привязать к человеку).
- Современный CSS (`oklch`, `color-mix`, `@layer`, container queries) по-прежнему требует свежих браузеров.
- Нет service worker (офлайн-режима), нет линтера; шрифты грузятся с Google Fonts.
- Подписи полей в модальных окнах админки и `alt` у картинок пользователей не доделаны.
- Нет проверки в реальном браузере (вёрстка полотна/прокрутки и новое меню проверены только по коду и в jsdom).
